# 2026-11-18 request spike — measurement and conclusion

Measured 2026-11-18T11:27Z–11:40Z via Cloudflare GraphQL (`workersInvocationsAdaptive`),
window `2026-11-16T00:00:00Z` → `2026-11-18T11:30:00Z`, scripts `arxivexplorer`,
`arxiv-api`, `arxiv-ingest`.

Status split inside 07:40–07:48:59: `success` 111,030, `exceededResources` 4,386,

Timeline:

- 07:33–07:37 ramp (≈1 k/min), 07:40 cliff to 12–13.8 k/min, 07:48 last full
  minute, 07:49 collapse to 1.9 k/min, **zero invocations from 08:00Z onward**.
- Day quota (100 k) was crossed in minute granularity at ≈07:45; edge
  enforcement (`Error 1027`, rejected before the Worker) starts at 08:00Z —
  which is why 08:00–11:30Z has no analytics rows at all while `/` returned
  429 at 10:59Z.

## What the burst hit

- `arxiv-api` received only ~250 invocations/min during the same window against
  12–13.8 k/min on `arxivexplorer` → **≈2 % of burst requests touched the
  backend**. A sitemap-driven crawl of paper/topic pages would be ~1:1.
- `arxiv-ingest`: 3 invocations (cron), not involved.
- Therefore the bulk were cheap Worker responses with no D1/KV/API work
  (unmatched paths / repeated low-cost routes), plus a CPU-heavy minority
  (4.4 k killed at the 10 ms budget).

## Ruled out

- Sitemap crawl of real paper pages (would show 1:1 api calls).
- Search/API storm (`/api/*` proxied to `arxiv-api` — flat at ~250/min).
- Ingest cron.
- Bot-block response (no 403 status series; the only statuses are success /
  exceededResources / clientDisconnected).

## Not determinable

UA, IP, country, path — `workersInvocationsAdaptive` exposes none of them, and
`log/logger.ts` is console-only (no persisted request log). Free plan has no
Workers Logpush / trace retention. Attribution is therefore impossible
retroactively; only aggregate shape is known.

Control days show no comparable event (11-16 peak hour 613, 11-17 peak hour
1,105) → the burst was one-off, not a repeating crawler cadence.

## Consequence

A bot block inside the Worker cannot protect the quota: the request is already
counted before the handler runs. Only paths served by the `ASSETS` binding skip
both the invocation count and the CPU budget (`/offline`, `/sw.js`, `/robots.txt`
proven 200 while `/` returned 429).

Free-plan levers, cheapest first:

1. Keep the existing graceful degradation (SW shell, `/offline`, cached RSS) —
   already deployed; this is the only zero-cost answer to 1027.
2. Shrink the CPU-heavy minority so `exceededResources` stops counting against
   the same day: early-return before React for unknown paths, cache negative
   lookups.
3. Prebuild informational routes as static assets (`public/faq.html` →
   `/faq`, same mapping already proven with `public/offline.html`) so crawler
   hits on those paths never invoke the Worker.
4. Real edge blocking (WAF / Bot Fight) requires a custom domain — out of scope
   under the "buy nothing" constraint, and a 111 k/9 min burst would exceed the
   free quota regardless of filtering placed after the edge counter.
